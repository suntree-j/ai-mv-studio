# 移动 App 路线图

## 定位

移动端做「轻量创作 + 预览 + 分享」，重计算全部放云端 GPU。

## 功能

| 模块 | 说明 |
|---|---|
| 选歌 | 内置曲库 / 上传本地音频 |
| 选音色 | 我的音色 / 社区音色（需授权） |
| 一键生成 | 创建任务 → 推送进度 → 完成通知 |
| 预览编辑 | 片段预览、重出某镜、歌词微调 |
| 导出分享 | 下载 MP4 / 分享到社交平台（带 AI 标识） |
| 账户 | 登录、历史项目、配额 |

## 技术选型

| 方案 | 说明 |
|---|---|
| **React Native + Expo** | 与 Web 共享 TypeScript 类型，迭代快 |
| Flutter | 性能好，但需另写 UI 层 |
| 原生 | 只在重度编辑需求时考虑 |

建议：**Expo + React Native**，复用后端 OpenAPI 生成客户端。

## 架构

```
App ──HTTPS──▶ API 网关 ──▶ FastAPI (任务)
                     │
                     └──▶ 对象存储（上传/下载）
                     │
                     └──▶ 推送（APNs/FCM）
```

## 里程碑

1. **M1**：登录 + 创建任务 + 进度 + 下载（2–3 周）
2. **M2**：内置曲库 + 音色选择 + 预览播放（2–3 周）
3. **M3**：逐镜重出、歌词微调、分享卡片（3–4 周）
4. **M4**：社区音色市场（需合规审查）（4 周+）

## 注意

- 移动端不做本地推理（模型太大）
- 上传大文件需分片 + 断点续传
- 生成内容必须带 **AI 合成标识**，禁止冒充原唱
